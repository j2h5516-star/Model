### 2단계. 터미널 열기

- **Windows**: `윈도우 키 + R` → `cmd` → 엔터
- **Mac**: `Command + 스페이스` → `터미널` → 엔터

### 3단계. 프로젝트 폴더로 이동

```bash
cd 내려받은폴더경로
```

### 4단계. 필요한 프로그램 설치 (최초 1회)

```bash
pip install -r requirements.txt      # Windows
pip3 install -r requirements.txt     # Mac
```

### 5단계. 실행

```bash
streamlit run app.py
```

> 명령을 못 찾는다고 나오면 — Windows: `python -m streamlit run app.py`,
> Mac: `python3 -m streamlit run app.py`
>
> 처음 실행 시 터미널에 `Email:` 이라고 물어보면 **엔터만** 누르면 됩니다.

## 🧮 점수는 이렇게 계산됩니다

### 펀더멘털 100점 (최종점수의 60%)

| 항목 | 배점 | 무엇을 보나 |
|---|---|---|
| **델타 가속** | 40 | 이익이 "얼마나" 늘었나가 아니라 **늘어나는 속도가 빨라지는가** |
| **GM% 드라이버** | 25 | 마진 개선이 물량형/믹스형/가격형 중 어느 것인가 |
| **매출 성장의 질** | 20 | 매출이 크게, 그리고 가속하며 크는가 |
| **포워드 신호** | 15 | 다음 분기 전망이 이번 분기보다 좋은가 + 애널리스트 상향/하향 |

**GM% 드라이버 구간** (최근 분기 GM% − 직전 4개 분기 평균)

| 변화 | 성격 | 점수 | 뜻 |
|---|---|---|---|
| ±1%p 이내 | 물량형 | 25 | 제품이 잘 팔려 규모가 커진 것 — **가장 건강** |
| +1 ~ +3%p | 믹스형 | 15 | 수익성 좋은 제품 비중이 늘어난 것 |
| +3%p 초과 | 가격형 | 5 | 가격 인상 효과 — 오래 못 갈 수 있음 |
| −1%p 초과 하락 | 마진 악화 | 8 | 수익성이 나빠지는 중 |

> 💡 **저기저(低基底) 함정 방지**: 최근 분기 논갭 영업이익이 **$50M 미만**이면
> 델타 가속 점수를 **절반(20점)까지만** 인정합니다.
> 비교 대상이 작으면 증가율이 실제보다 커 보이는 착시가 생기기 때문입니다.

**가속/감속은 두 신호를 함께 봅니다** (한 분기만 튀어도 판정이 뒤집히지 않도록)

| 신호 | 계산 | 성격 |
|---|---|---|
| ① 단기 | 최근 QoQ 증가율 − 직전 QoQ 증가율 (±3%p 기준) | 민감함 |
| ② 추세 | 최근 4개 QoQ 증가율의 **회귀 기울기** (±1.5 기준) | 안정적 |

- 두 신호가 **같은 방향** → `가속` 또는 `감속` (확신 높음)
- 두 신호가 **서로 반대** → `혼조` — 억지로 한쪽으로 정하지 않고 솔직히 표시합니다

**델타 예측** (다음 분기 전망치로 앞으로의 방향을 미리 봅니다)

| 표시 | 뜻 |
|---|---|
| `가속 지속 ↗↗` | 탄력이 더 붙는 중 |
| `가속 둔화 ↗↘` | 정점 근처 가능성 |
| `감속 지속 ↘↘` | 계속 느려짐 |
| `반등 ↘↗` | 바닥 통과 가능성 |

## 🔍 데이터를 모으는 방법 (전부 자동)

### 1) 실적 — 미국 SEC 전자공시(EDGAR)

`edgartools` 라이브러리로 각 종목의 **8-K(Item 2.02 = 실적발표)** 공시에 첨부된
보도자료를 자동으로 읽어, 아래 순서로 논갭 영업이익을 확보합니다.

| 순서 | 방법 | 화면 배지 |
|---|---|---|
| ① | 보도자료의 GAAP→non-GAAP 조정표에서 **non-GAAP operating income** 을 직접 추출 (`adjusted operating income` 등 표기 변형도 인식) | `직접공시` |
| ② | 직접 공시가 없으면 **매출 × non-GAAP GM% − non-GAAP 영업비용** 으로 역산 | `역산` |
| ③ | 그래도 실패하면 SEC **XBRL**로 `GAAP 영업이익 + 주식보상비 + 무형자산상각`, GM%는 GAAP 값 사용 | `근사치` |

**수집 구조** — "둘 중 하나"가 아니라 **합칩니다**

```
① XBRL로 전체 분기 뼈대를 만든다  (빠진 4분기도 계산해 채움)
② 8-K 보도자료에서 논갭 수치를 뽑는다
③ 성공한 분기만 ①에 덮어쓴다 → 분기마다 개별 출처 배지
```

이 구조 덕분에 8-K가 **일부만 성공해도** 그 분기는 `직접공시`로 올라가고,
나머지 분기는 `근사치`로 유지됩니다. (예전에는 하나라도 실패하면 전부 근사치였습니다)

> 🔧 **빠진 4분기 채우기**: 회사는 1~3분기만 10-Q에 3개월 단위로 신고하고,
> **4분기는 10-K에 연간으로만** 신고합니다. 그래서 3개월짜리만 모으면 매년 4분기가
> 통째로 빠집니다. `Q4 = 연간 − (Q1+Q2+Q3)` 로 계산해 채워, 표본이 **연 3개 → 4개**가 됩니다.

- 수집 기간: **3년(12분기)** — 가속/감속 판정을 안정적으로 하려면 표본이 필요합니다.
  화면은 기본적으로 2025년부터 보여주고, 사이드바 **전체 이력 보기**로 3년치를 볼 수 있습니다
- 정렬은 **8-K 제출일(발표일) 기준**
- SEC 요청 시 신원 헤더를 설정하고 요청 제한을 지킵니다
- 받은 데이터는 `data/` 폴더에 저장해 **재실행 시 다시 내려받지 않습니다**

> 🔒 **SEC 요청자 신원을 비공개로 설정하려면** (선택 사항)
>
> 저장소가 공개라 개인 이메일을 코드에 넣지 않았습니다. 기본값으로도 동작하지만,
> SEC 권장대로 실제 연락처를 넣고 싶다면 **비공개**로 설정할 수 있습니다:
>
> Streamlit 앱 화면 오른쪽 아래 **⋮ → Settings → Secrets** 에 아래 한 줄을 넣고 저장
> ```
> SEC_IDENTITY = "홍길동 mymail@example.com"
> ```
> Secrets는 저장소에 올라가지 않아 다른 사람이 볼 수 없습니다.

`+1`(상향) / `0`(중립) / `−1`(하향)을 자동 산출합니다.

### 4) 데이터 신뢰도 (6단계)

숫자를 **어떻게 구했는지**에 따라 신뢰도를 매겨 화면에 표시합니다.

| 순위 | 종류 | 신뢰도 | 무엇인가 |
|---|---|---|---|
| 1 | `직접공시` | **95%** | 회사 보도자료의 논갭 영업이익 원문 그대로 |
| 2 | `가이던스` | **85%** | 회사가 직접 발표한 다음 분기 전망 |
| 3 | `역산` | **75%** | 공시된 매출 × 마진 − 비용으로 계산 |
| 4 | `근사치` | **55%** | XBRL 회계데이터로 만든 근사치 |
| 5 | `추정` | **40%** | 애널리스트 매출 전망 × 과거 평균 마진 |
| 6 | `없음` | **0%** | 자료를 구하지 못함 |

**종합 신뢰도 = 실적 신뢰도 × 0.7 + 전망 신뢰도 × 0.3**
(실적 신뢰도는 분기별 출처의 가중평균, 최근 분기일수록 큰 가중치)

> **신뢰도는 점수에 반영하지 않습니다.** 순위는 그대로 두고 참고용으로만 표시합니다.
> 퍼센티지는 자료의 성격을 고려해 정한 값이며 통계로 검증된 수치가 아닙니다
> (`config.py`의 `CONFIDENCE_TIERS`에서 조정 가능).

- **포워드는 진짜 컨센서스가 아닙니다.** 무료 데이터로는 월가 컨센서스를 구할 수 없습니다.
  `가이던스` 배지는 회사 발표에 근거하지만, `추정` 배지는 **통계적 추정치**입니다.
  실제 결과와 다를 수 있습니다.
- **`근사치` 배지가 붙은 실적**은 회사가 발표하는 공식 논갭 수치와 차이가 날 수 있습니다.
  XBRL의 GAAP 값에 주식보상비·무형자산상각만 되돌린 값이기 때문입니다.
- **보도자료 형식은 회사마다 다릅니다.** 파싱이 완벽하지 않을 수 있으니,
  중요한 판단 전에는 화면의 **원본 숫자 표**와 실제 공시를 확인하세요.
- **주가는 15분 이상 지연**될 수 있습니다.
- SEC 서버가 느릴 때를 대비해 실적 수집에 **시간 제한**을 두었습니다.
  제한을 넘긴 종목은 "실적 데이터를 찾지 못함"으로 표시되고 주가 지표만 반영됩니다.

## ❓ 문제 해결 (FAQ)

**Q. "This repository does not exist" 라고 나와요.**
→ 저장소가 비공개입니다. GitHub Settings → Danger Zone → Change visibility → public 으로 변경하세요.

**Q. 첫 화면이 너무 오래 걸려요.**
→ 정상입니다. SEC에서 13개 종목의 공시를 모두 읽기 때문에 첫 실행은 1~3분 걸립니다.

**Q. 특정 종목만 "실적 데이터를 찾지 못했습니다" 라고 나와요.**
→ 보도자료 형식이 특이하거나 SEC 응답이 느렸을 수 있습니다. **🔄 데이터 새로고침**을 눌러 보세요.
그래도 안 되면 그 종목은 주가 지표(기술 점수)만 반영됩니다.

**Q. 점수가 갑자기 바뀌었어요.**
→ 새 분기 실적이 발표되면 델타 가속·GM% 드라이버 값이 바뀌어 점수가 크게 움직일 수 있습니다.

**Q. 종목을 추가하고 싶어요.**
→ `config.py` 의 `TICKERS` 목록에 티커를 넣고 저장한 뒤, GitHub에 올리면 앱이 자동으로 갱신됩니다.
