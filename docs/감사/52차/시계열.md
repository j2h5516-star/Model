## 3. period_label 이 filing_date 와 어긋나는 행

회계연도 오프셋(NKE·WMT 등)에 속지 않도록 **오프셋에 무관한 검사**를 썼습니다:
한 종목 안에서 제출일 순으로 정렬하면 라벨 순번(연*4+분기)은 반드시 증가해야 합니다.

Q형 라벨 2,787행 중
- **역행** (제출일은 뒤인데 라벨은 앞): **84건 / 37종목**
- **정체** (제출일이 다른데 라벨이 같음): **93건 / 39종목**
- 합쳐 **177행 / 56종목**

source 별: 역행 = 역산38·직접공시30·근사치16 / 정체 = 역산54·근사치29·직접공시10.
**직접공시 행에서도 40건**이 나옵니다 — 파싱 실패가 아니라 라벨 추출 자체의 문제입니다.

실측 예:
```
JPM  2024-05-15 '24 Q2' → 2024-07-12 '23 Q3'   (라벨이 3분기 뒤로 감)
NFLX '20 Q4' 가 2021-09-30 ~ 2022-12-31 의 6개 제출일에 계속 붙어 있음
VZ   '23 Q1' 이 2023-03-31 ~ 2024-06-30 의 6개 제출일에 계속 붙어 있음
CMCSA '23 Q1' 4행 · GE '23 Q1' 4행 · INTC '23 Q1' 4행
WMT  2022-10-31 '23 Q4' → 2023-01-31 '22 Q1'
```
`extract_period_label`(sec_fundamentals.py:967) 은 본문에서 "first quarter … 20XX" 를
정규식으로 집는데, 실적 이외 문서·전년 비교 문장을 집으면 그대로 굳습니다.

**영향 범위 (정확히)**: `measure_engine` 은 period_label 을 쓰지 않습니다
(구간은 filing_date, 시점은 announced_date). 따라서 신고점 측정은 직접 오염되지 않습니다.
오염되는 곳은 `data_quality.fiscal_quarter`(340행) → **전년동기 짝짓기**와 화면 차트 가로축입니다.
data_quality 주석에 적힌 "인덱스로 4칸 뒤" 사고를 막으려고 만든 장치가,
라벨이 틀리면 같은 방식으로 틀립니다.

## 4. source 분포와 역산 행의 신뢰도

### 4-1 분포 (3,068행)
```
직접공시 1,343행 (43.8%)   역산 625행 (20.4%)   근사치 1,100행 (35.9%)
```
칸 채움률:
```
직접공시 : revenue 99% op_income 100% adj_eps 85% ebitda  7% gaap_eps 93%
역산     : revenue 92% op_income  29% adj_eps 43% ebitda 18% gaap_eps 85%
근사치   : revenue100% op_income 100% adj_eps 41% ebitda 13% gaap_eps 74%
```
**"역산" 행의 71% 는 op_income 이 아예 없습니다.** 역산의 정의는
"매출 × 논갭 GM% − 논갭 영업비용"(sec_fundamentals.py:13) 인데,
그 계산 결과인 op_income 이 없는 행에 역산 배지가 붙어 있습니다 — 배지가 실제 유래를 말하지 않습니다.

### 4-2 직접공시가 한 번도 없는 종목 = 68 / 160
근사치 100% 종목 **29개**: LITE FN QCOM TXN TER CIEN TSLA FSLR META AMZN ABNB PWR NEE SO RUN 등
역산 100% 종목(금융·제약 중심) **12개 이상**: ETN JPM BAC WFC C GS MS SCHW AXP COF LLY JNJ

### 4-3 역산 행이 직접공시 행과 이어 붙을 때 튀는가 — **튑니다**
영업이익률(op/revenue)의 인접 분기 점프를 source 가 같을 때/바뀔 때로 나눠 쟀습니다
(매출 1천만 달러 이상 행만, dataset.build 정제 후):

| 이음매 | n | 마진 점프 중앙값 | >10%p 비율 | >30%p |
|---|---|---|---|---|
| **같은 source** | 1,355 | **2.17%p** | 15% | 50 |
| **source 경계** | 137 | **12.06%p** | 56% | 34 |

**중앙값 기준 5.5배.** 정제 전 원본으로는 1.56%p vs 13.27%p (8.5배)로 더 벌어집니다.
역산이 한쪽에 낀 경계 103건의 중앙 점프는 13.90%p.

가장 튄 경계 (정제 후):
```
T    2022-12-31 근사치 -67.3%  → 2023-03-31 직접공시  19.9%   (87.2%p)
MXL  2024-09-30 역산   -31.1%  → 2024-12-31 직접공시  49.1%   (80.2%p)
MDB  2021-10-31 근사치  -3.6%  → 2022-01-31 역산      74.0%   (77.6%p)
DIOD 2026-06-30 근사치  10.9%  → 2026-08-12 역산     -60.3%   (71.2%p)
CMCSA 역산 -21.1% ↔ 근사치 +46.0%  (2023·2024·2025 세 해 모두 같은 패턴 반복)
```
### 4-4 CMCSA — source 가 이익의 **부호**를 정하고 있음 (가장 선명한 실물)
CMCSA 20분기를 전부 찍어 보면 (외부 지식 없이 저장된 값만):
```
역산  행 10개 : op_income 전부 음수  (-3,331M ~ -3,862M, 마진 -11.2% ~ -22.3%)
근사치 행 10개 : op_income 전부 양수  (+5,533M ~ +8,304M, 마진 +31.4% ~ +46.5%)
```
**적자/흑자가 실적이 아니라 source 로 갈립니다.** 게다가 3월 제출분은 항상 역산(음수),
나머지 분기는 항상 근사치(양수)라 해마다 같은 톱니가 반복됩니다:
`-3,775 → +8,304 → +8,003 → +6,056 → -3,549 → +8,283 → ...`
이 톱니는 "이익 델타(연속 분기 증감)"의 **부호를 매년 네 번 뒤집습니다.**

같은 형태(한 source 는 전부 적자·다른 source 는 전부 흑자, 각 3건 이상)를 전수 검사한 결과
**3종목**이 나왔습니다:
```
CMCSA 역산 10건 전부 적자 / 근사치 10건 전부 흑자
ZETA  근사치 4건 전부 적자 / 역산   7건 전부 흑자
BE    근사치 5건 전부 적자 / 직접공시 7건 전부 흑자
```
덧붙여 CMCSA 는 2023-03-31 을 경계로 매출이 **30,552M → 17,869M 로 반토막**나는데
(부문 범위 변경으로 보임) 이 역시 시계열 안의 구조적 단절입니다.

## 5. announced_date 없는 행

**165행 / 45종목** (전체 3,068행의 5.4%). 전부 없는 종목은 없습니다.
많은 순: NXPI 9 · DIOD 9 · APP 8 · PG 8 · TSLA 7 · COST 7 · STRL 6 · CAT 6 · T 6 · SMCI 5.

**정점 기억에는 참여하지만 측정 사건이 되지 못합니다** (설계대로이며 창작 금지 원칙에 맞음).

announced_date 중복(같은 날 두 발표)은 6종목: COF·GE·JNJ·JPM·PFE·TTMI.
`earnings_states` 의 `seen` 집합이 **먼저 오는 행 하나만** 채택하는데,
정렬은 filing_date 기준이라 **어느 쪽이 진짜인지와 무관하게 앞의 행이 이깁니다.**
JPM 의 경우 배당 행과 실적 행이 같은 날에 있어, 어느 것이 채택되는지가 우연에 달려 있습니다.

## 6. 검사했지만 문제가 없던 것

- `filing_date` 형식 오류·결측: **0행** (3,068행 전부 YYYY-MM-DD 유효).
- 시간 정렬: `dataset._clean_quarters` 가 filing_date 로 정렬 보장 — 확인됨.
- 라벨 형식은 두 종류뿐 (Q형 2,787 / 슬래시형 281) — 알 수 없는 형식 0건.
- `eps_runs` 의 55~150일 규칙 자체는 의도대로 동작합니다. 구간이 끊기는 것은
  **규칙의 결함이 아니라 입력 데이터의 결함**입니다 (장치를 먼저 의심하는 원칙에 따라
  규칙을 먼저 읽었고, 규칙 쪽에서는 결함을 찾지 못했습니다).
- `dataset.py` 의 단위 가드(영업이익 마진, EBITDA, 주당금액 상한)는 실제로 작동합니다:
  CAT 1166% · ACLS 179% · GILD -133% 같은 극단값이 정제 후 사라졌습니다.

## 7. 확인하지 못한 것

- 각 분기의 값이 회사 발표와 맞는지는 **JPM 1건만 원문으로 검증**했습니다.
