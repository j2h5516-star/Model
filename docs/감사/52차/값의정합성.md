## 1. [치명] 주식분할이 EPS 에만 반영 안 됨 — 7종목이 신고점을 영원히 못 냅니다

**가격은 분할 조정돼 있는데 EPS 계열은 조정 전 값이 그대로 남아 있습니다.**

가격이 분할 조정임을 확인 (실행 출력):
```
NVDA  2024-06-10 종가 121.58   GOOGL 2022-07-18 종가 108.07
AVGO  2024-07-15 종가 168.26   LRCX  2024-10-03 종가  79.98
(전부 분할 후 가격대)
```

EPS 계열은 조정 전:
```
NVDA  adj_eps  ... 5.16 → 6.12 → 0.68 → 0.81 → 0.89      (10:1)
GOOGL gaap_eps ... 22.3 → 26.29 → 1.36 → 1.40 → 1.53     (20:1)
AVGO  adj_eps  ... 11.06 → 10.96 → 1.24 → 1.60 → 1.58    (10:1)
LRCX  adj_eps  ... 8.14 → 8.60 → 0.91 → 1.04 → 1.33      (10:1)
SMCI  adj_eps  ... 7.62 → 22.09 → 0.56 → 0.46 → 0.40     (10:1)
ANET  adj_eps  ... 2.10 → 2.40 → 0.65 → 0.65 → 0.73      (4:1)
WMT   adj_eps  ... 1.53 → 1.80 → 0.60 → 0.67 → 0.58      (3:1)
```

**산술 검산 (내재 PER = 주가 ÷ TTM EPS)** — 단차 앞뒤로 PER 이 급등:
```
AVGO  2023-12-07 TTM 42.25 주가  89.4 → PER  2.1  ||  2025-12-11 TTM 6.82 주가 404.1 → PER 59.3   (x28.2)
SMCI  2025-05-06 TTM 23.51 주가  32.9 → PER  1.4  ||  2025-08-05 TTM 1.82 주가  57.3 → PER 31.5   (x22.5)
GOOGL 2023-02-02 TTM 30.58 주가 106.8 → PER  3.5  ||  2024-04-25 TTM 4.49 주가 154.6 → PER 34.4   (x 9.8)
LRCX  2025-07-30 TTM 11.88 주가  98.5 → PER  8.3  ||  2025-10-22 TTM 4.54 주가 140.7 → PER 31.0   (x 3.7)
NVDA  2025-02-26 TTM  8.50 주가 131.1 → PER 15.4  ||  2025-05-28 TTM 3.14 주가 134.6 → PER 42.9   (x 2.8)
```
PER 2.1(AVGO)·1.4(SMCI)·3.5(GOOGL) 은 이 회사들에서 존재할 수 없는 값입니다.
즉 **분할 후 주가에 분할 전 EPS 를 붙여 놓은 것**이 산술로 증명됩니다.

**측정에 미치는 영향 (measure_engine.earnings_states 실제 실행 출력)**
```
NVDA  분할 후 판단가능 발표  8건, 신고점 0건   분할전 TTM 최고 18.00 → 분할후 TTM 3.14~4.03
GOOGL 분할 후 판단가능 발표 12건, 신고점 0건
AVGO  분할 후 판단가능 발표  3건, 신고점 0건   분할전 TTM 최고 42.25 → 분할후 6.82
LRCX  분할 후 판단가능 발표  8건, 신고점 0건   분할전 TTM 최고 36.95 → 분할후 4.54
SMCI  분할 후 판단가능 발표  8건, 신고점 0건   분할전 TTM 최고 39.31 → 분할후 1.82
ANET  분할 후 판단가능 발표  7건, 신고점 0건
WMT   분할 후 판단가능 발표  9건, 신고점 0건
──────────────────────────────────────────────
합계 55건 판단가능 발표 · 신고점 0건
```

모델의 핵심 신호는 "TTM 조정 EPS 신고점 **첫** 돌파"입니다.
EPS 가 10~20배 낮아진 채로 굳으면 **TTM 이 과거 정점을 다시 넘는 일이 물리적으로
불가능**합니다. NVDA·GOOGL·AVGO·LRCX·SMCI·ANET·WMT — 유니버스에서 가장 중요한
성장주 7종목이 **구조적으로 신호에서 배제**돼 있습니다. 게다가 NVDA 는 TTM 이
18.00 → 3.14 로 "83% 이익 급감"처럼 읽혀, 이익 델타·주도섹터 판정을 반대로 뒤집습니다.

이건 "값이 조금 틀림"이 아니라 **가설 검정의 표본이 조용히 잘려 나가는 문제**입니다.
채택 기준(윌슨 하한 > 기준선 상한, n≥10)을 다투는 상황에서 55건 소실은 결정적입니다.

탐지 방법(재현): `.../audit/steps.json`, `splits.json`, `per_scan.json`

## 5. [중대] 매출과 영업이익의 단위가 서로 다름 — 가드가 **아예 안 걸립니다**

`dataset.py` 의 영업이익·EBITDA 마진 가드는 `revenue >= 10,000,000` 일 때만 작동합니다.
그런데 매출이 **천/백만 단위로 저장된 행**에서는 이 조건이 거짓이 되어
**가드가 통째로 건너뛰어집니다.**

```
가드 통과 후에도 남은 이상 영업이익 (매출 >= 1천만):     0건   ← 가드는 잘 작동
가드가 아예 안 돌아간 이상 영업이익 (매출 < 1천만):     85건   ← 구멍
가드가 아예 안 돌아간 이상 EBITDA:                       0건
```
85건의 종목 15개: **FSLR 20 · TER 17 · TGT 16 · HD 9 · U 5 · META 4 · GNRC 3 · VST 3 ·
AMZN 2 · ZETA·NFLX·NRG·HPE·SBUX·UPS 각 1**

예 (실행 출력):
```
META 21 Q3: 매출 29,010 · 영업이익 12,802,000,000 → 마진 44,129,610%
TGT  21 Q3: 매출 25,652 · 영업이익  2,010,000,000 → 마진  7,835,646%
FSLR 23 Q4: 매출 413,579 · 영업이익 408,794,000  → 마진     98,843%
```
한 회사 안에서 매출 단위가 섞인 종목 **21종목**(log10 폭 ≥ 2), 어긋난 행 47건:
AMZN 6.86 · META 6.34 · XOM 6.18 · GE 6.12 · TGT 6.11 · BMY 6.03 · UPS 5.99 ·
HPE 5.87 · AMD 5.82 · VST 5.38 · ZETA 4.63 · NRG 4.50 · COF 4.38 · SBUX 3.97 ·
GNRC 3.87 · U 3.63 · TER 3.35 · NFLX 3.06 · AXP 2.51 · C 2.37 · PFE 2.13

**완화 요인(정직하게)**: `op_income` 은 잣대 사다리에 없고 `app.py` 화면 표시에만
쓰입니다(`grep` 확인: measure_engine·leadership·sector_model 에 op_income 없음).
따라서 신고점 판정은 직접 오염되지 않습니다. 다만 **화면 숫자가 틀리고**,

## 7. [경미] period_label 이 신고일과 어긋남 — 화면 표기만의 문제

```
SCHW: 2025-01-21 / 2025-04-17 / 2025-07-18 / 2025-10-16 네 발표가 전부 '24 Q4'
      (값 1.01·1.04·1.08·1.26 은 각 분기 실제값과 맞음 — 라벨만 고정됨)
XOM : 2022-07-29 발표가 '23 Q1', 2024-02-02 발표가 '24 Q2', '24 Q1' 이 3번 등장
BAC : '25 Q1' 라벨이 5개 서로 다른 날짜에 등장
```
측정은 `announced_date` 기준(55~150일 간격)이라 판정에는 영향이 없지만
계기판에서 사용자가 읽는 분기 이름이 틀립니다.

## 8. adj_eps ↔ gaap_eps 괴리 — **검사했으나 대부분 정상이었습니다**

adj/gaap 비율 10배 초과 또는 부호가 반대인 행 144건을 뽑아 봤으나,
대다수는 SaaS 기업의 정상적 특성(주식보상비 때문에 GAAP 이 0 근처)이었습니다:
DDOG 0.46/0.01 · CRM 0.98/0.03 · CRWD 0.74/0.03 · ZS 0.84/-0.03 · HUBS 2.56/-0.06.
**이 축에서는 새 오류를 찾지 못했습니다.** 여기서 문제라고 적었으면 없는 문제를
만드는 것이었습니다. 다만 SNDK 25 Q2 (13.19 vs 0.01) 와 IPGP 24 Q4 는
다른 절에서 이미 잡힌 값입니다.

## 9. 그 밖에 검사했고 깨끗했던 것

- `dataset.py` 매출 하한(1만 달러) 가드: S 22 Q4 매출 74.0 · APP 등 실제로 막고 있음 — 정상 작동

- NaN/무한대/날짜형식 검사: notes 1,106건에 전부 기록됨 — 조용한 삭제 없음

## 우선순위 제안 (고치지 말고 "없음"으로 두는 원칙에 맞춰)

1. **분할 미조정 7종목** — 이건 "없음 처리"로 해결 안 됩니다. 분할 계수를 적용하거나,
   최소한 단차 이전 구간을 잘라내야 합니다. 지금은 55건 표본이 조용히 사라진 상태입니다.
2. **주당값 상한을 100 → 훨씬 낮게, 또는 "회사 중앙값의 N배" 상대 기준으로.**
   99.1 하나가 가짜 첫 돌파(H2b) 1건을 만들었습니다.
3. **가드의 `revenue >= 10_000_000` 조건이 구멍입니다.** 매출 단위가 무너진 행에서는
   가드가 안 돕니다. 매출 자체의 단위 검사(같은 회사 안 log10 일관성)를 먼저 해야 합니다.
4. **UCTT 형 주식수 오집기** — "Shares used in computing..." 다음 숫자를 EPS 로 읽는 경로 차단.
5. REGN·GILD 처럼 **한 회사 안에서 값이 두 무리로 갈리는지**를 로봇이 매일 자가 점검하도록.
