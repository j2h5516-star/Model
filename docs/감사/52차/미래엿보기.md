## F1 (치명) — 잣대 사다리(`measure_engine.yardstick_of`)가 미래 분기를 본다

### 무엇이 문제인가

`yardstick_of(rows)` 는 **그 종목의 분기 전부**를 세어 조정 EPS ≥ 8분기면 조정 EPS,
아니면 EBITDA, 아니면 GAAP EPS 로 잣대를 고정합니다. `rows` 에는 그 사건 **이후**에
발표된 분기까지 들어 있습니다. 즉 2022년 사건을 잴 때 "이 회사는 2026년까지
조정 EPS 가 8분기 이상 쌓일 것"이라는 미래 지식을 쓰고 있습니다.

`sector_model.yardstick_of_safe` → `_delta_series` 도 같은 함수를 부르므로
이익 델타 · 주도섹터 판정까지 같은 오염을 물려받습니다.
`collect_metric_events(ds, field, min_quarters=8)` 의 종목 걸러내기도 같은 구조입니다.

### 재현 코드
`/tmp/.../scratchpad/audit/out/` 옆에 두지 않고 아래를 그대로 붙여 넣으면 재현됩니다.
```python
import dataset, measure_engine as me, judge
ds = dataset.build(dataset.load()); spy = ds['prices'][ds['benchmark']]
series = me.gauge_series(ds)
pit=[]
for t in ds['tickers']:
    rows = ds['quarters'].get(t) or []; prices = ds['prices'].get(t)
    if not prices or not prices.get('dates'): continue
    for d in sorted({str(r['announced_date'])[:10] for r in rows if r.get('announced_date')}):
        known=[r for r in rows if r.get('announced_date') and str(r['announced_date'])[:10]<=d]
        f = me.yardstick_of(known)
        if f is None: continue
        st=[s for s in me.earnings_states(known, field=f) if s['announced']==d]
        if not st: continue
        ex,_=me.excess_return(prices, spy, d)
        if ex is None: continue
        pit.append({'ticker':t,'잣대':f,'announced':d,'new_high':st[-1]['new_high'],
          'newhigh_streak':st[-1]['newhigh_streak'],'h5':me.gauge_h5_on(series,d),
          'h5b':me.gauge_h5b_on(series,d),'below52':me.below_52wk_ma(prices,d),'excess':ex})
pit.sort(key=lambda e:e['announced']); print(judge.run(pit))
```

### 제안
잣대는 사건 시점까지 알려진 분기로만 고르거나(PIT), 최소한 두 판을 나란히
보고해 얼마나 흔들리는지 드러내야 합니다. **판정 문서에 PIT 판을 병기하지 않으면
H9 채택은 근거가 없습니다.**

## F3 (중대) — 주가가 배당 반영 수정주가라서 과거 가격이 미래로 되쓰인다

```
market_data.py:60      auto_adjust=True,      # 액면분할·배당 반영된 수정주가 사용
market_data.py:90-91   if "Close" not in df.columns and "Adj Close" in df.columns: rename
```

배당 조정은 배당락일 **이전의 모든 과거 가격**을 (1 − 배당/주가) 만큼 내립니다.
그래서 오늘 저장된 2022년 종가는 2022년에 화면에 떠 있던 종가가 아니라,
2022~2026년에 지급될 배당을 미리 반영해 깎아 놓은 값입니다.

영향 범위: `aligned_flags` · `aligned_flags_chart`(정배열 완성) ·
`gap_over_52w`(H18 이격도) · `below_52wk_ma`(H9·H10 신호) — **가격 신호 전부**.
52주 창 안에 배당락일이 있으면 창의 앞부분만 추가로 깎여 시계열이 위로 기울고,
이는 **정배열 방향으로 편향**됩니다.

### 정직한 한계
스냅샷 깃 이력이 3일치(2026-08-13 ~ 08-15)뿐이라 **되쓰기 폭을 실측하지 못했습니다.**
이틀 간격 비교에서는 80종목 중 25종목의 과거 종가가 바뀌었으나 최대 변동이
0.001% 로 반올림 수준이었습니다(그 이틀 사이 배당락이 거의 없었던 것으로 보입니다).
즉 **되쓰기가 일어난다는 것은 확인했고, 배당으로 인한 크기는 확인 못 했습니다.**

`근사치` = SEC XBRL 의 GAAP 영업이익 + 주식보상비 + 무형자산상각
(sec_fundamentals.py:12-14, 1480-1530). XBRL 은 10-Q 에서 나오는데,
10-Q 는 보통 8-K(보도자료)보다 며칠~수 주 뒤에 제출됩니다.
신호일은 8-K 날짜이므로, 그 시점에 10-Q 숫자를 알 수 없었을 수 있습니다.
이 값은 H10(논갭 영업이익 단독 사건, `collect_metric_events(ds,"op_income")`)의
신호 재료입니다(collect_job.py:138).

**확정하지 못했습니다.** 이유: `filing_date` 에 실제 10-Q 제출일이 저장되어 있지 않습니다 —
sec_fundamentals.py:1631 에 `"filing_date": period_end,  # 실제 제출일 대신 기간종료일 사용`
이라고 명시돼 있습니다. 또 근사치의 재료(GAAP 영업이익·주식보상비)는 보도자료에도
흔히 실리므로, 사실상 8-K 시점에 알 수 있었을 가능성도 큽니다.
→ **제출일을 스냅샷에 저장하기 전에는 이 항목을 판정할 수 없습니다.**

# 검사했는데 문제 없었던 것 (없는 문제를 만들지 않기 위해 그대로 적습니다)

### ① 진입일이 신호일보다 앞서는 곳 — 없음
```
사건 2366 · 건너뜀 {'주가없음': 0, '우측검열': 134, '주가시작전': 0, '잣대없음': 9, '기타': 0}
진입일 <= 발표일 사건: 0
```
`window_return` 의 `bisect_right(dates, announce)` 가 발표일 **다음** 거래일을 잡고,
`ENTRY_MAX_GAP_DAYS=10` 으로 주가 이력이 늦게 시작한 경우도 막습니다.
`sector_model._forward_excess` · `leadership.group_excess` 도 같은 방식(`bisect_right(dates, day)`)이며,
`_backward_excess` 만 의도적으로 과거 창(H21 "분기점 직전")을 봅니다 — 등록문 그대로입니다.

### ② 이동평균·52주선·이격도가 미래 가격을 포함하는가 — 아니오
가격 시계열을 절반에서 자른 뒤 같은 날짜의 값을 재계산해 원본과 비교했습니다
(1,200거래일 이상 158종목 중 무작위 25종목):
```
절단 재계산 검사 4150 불일치 0
```
검사 대상: `aligned_flags`(33차 정배열 폭) · `aligned_flags_chart`(39차 정배열 완성) ·
`gap_over_52w`(H18 이격도) · `below_52wk_ma`(H9·H10). 넷 다 인과적입니다.
`weekly_indices`/`weekly_grid` 도 각 주의 마지막 거래일만 뽑을 뿐 미래를 보지 않습니다.

주의: 이건 **계산 방식**이 인과적이라는 뜻이고, **입력 가격 자체**는 F3(배당 수정주가)에
걸립니다. 절단 시험은 같은 오염된 시계열끼리 비교하므로 F3 은 잡히지 않습니다.

### ③ `leadership.confirmation_events` — 미래 발표를 쓰지 않음
지시받은 항목입니다. 코드가 `after = [s for s in series if s[0] > 완성일 and s[0] <= day]`
로 현재 주 상한을 걸고 있고, 실측으로도:
```
확인사건 47건 · 확인사건이 미래 발표를 쓴 건수: 0
  2023-01-20 금융 중개·자본시장 2/3 · 2023-02-17 기기 OEM 반도체 2/3 ·
  2023-05-19 소비 최종재·유통 2/4 · 2023-06-16 좌석·계약 정액 구독 소프트웨어 3/3 ...
```
`weekly_group_state` 의 `완성일`·`완성종목` 도 `start < row[0] <= day` 로 잘려 있습니다.
`leadership_timeline` · `inflection_events` 도 주 순서대로 앞에서 뒤로만 걷습니다.

### ④ `dataset.py` 의 값 검사가 전체 시계열을 보는가 — 아니오
지시받은 항목입니다. `_clean_quarters` 의 모든 검사는 **한 행 안에서만** 끝납니다:
날짜 형식, 숫자 여부(NaN/inf), 매출 하한 10,000, 영업이익/매출 마진 가드,
조정 EBITDA/매출 비율 가드, 주당 금액 상한 100. 다른 분기·다른 시점 값을 참조하는
곳이 없습니다. `_clean_prices` 도 점 단위(0 이하·형식 오류·중복 날짜)만 봅니다.
시계열 전체를 보는 판단은 딱 하나 — 날짜 개수와 종가 개수가 다르면 그 종목 가격을
통째로 버리는 것 — 인데, 이는 정보를 **빼는** 쪽이라 미래를 주입하지 않습니다.

### ⑤ 사후 정보 `유지주`(완성 후 정배열 유지 주수)의 사용처 — 없음
`sector_model.completion_events` 는 미래를 보고 `유지주` 를 계산해 사건에 담지만,
grep 결과 판정·화면 어디에서도 쓰지 않습니다(`sector_model.py` 정의부와
`tests/test_sector_model.py:103` 뿐). 주석에도 "매매 규칙으로 쓸 수 없습니다"라고
적혀 있습니다 — 규율이 지켜지고 있습니다.

### ⑥ `gauge_h5b_on` 의 중앙값 이력 — 현재 주를 제외
`history = [v for v in series["values"][:idx] if v is not None]` — 현재 주 값이
자기 자신의 중앙값에 들어가지 않습니다. 워밍업 52주 미만이면 판단 불가(None).

### ⑦ `filing_date` 순서와 `announced_date` 순서 — 역전 0쌍
`earnings_states` 는 `filing_date` 순으로 걸으며 과거 정점(`past_peak`)을 쌓고
결과를 `announced_date` 로 다시 정렬합니다. 두 순서가 어긋나면 나중에 발표된
분기의 정점을 먼저 세는 미래 엿보기가 생기는데, 실측 결과:
```
filing순서와 announced순서 역전 쌍: 0
announced_date < filing_date 인 행: 0
```
안전합니다. 다만 `filing_date` 의 의미가 섞여 있습니다 — XBRL 유래 행은 기간종료일
(sec_fundamentals.py:1631), 보도자료 유래 행은 8-K 제출일(announced==filing 인 497행).
`eps_runs` 의 55~150일 간격 판정이 이 섞인 축 위에서 돌아갑니다.
미래 엿보기는 아니지만 축 1·2 에서 볼 값입니다.

### ⑧ H18·H19b 의 등록일 컷 — 규율 지켜짐
`sector_model.H18_START_DAY = leadership.H19B_START_DAY = "2026-08-15"` 로,
등록일 **뒤**의 사건만 판정 표본에 넣고 그 전 것은 "탐색표본(참고)" 칸에만
넣습니다(judge.py:235-260, judge.judge_leadership). 탐색 표본 재사용 금지 원칙 5 를
코드가 실제로 집행하고 있습니다.
