### F3 (보통) — 원장 행에 "어느 분기 추정인가" 라벨이 없다 + 발표 직후 0q 가 옛 분기를 가리킨 실증 2건
원장 행 키: `avg, low, high, analysts, year_ago, rev_avg, rev_low, rev_high, rev_analysts`.
**대상 분기를 적는 칸이 없다.** 지금은 `year_ago` 로 역추정해야만 알 수 있다(내가 그렇게 했다).

실제로 어긋난 사례 2건 (원장 추정치가 이미 발표된 분기의 보관 est 와 완전 일치):
```
CSCO 2026-08-14 0q avg 1.16883 → 실은 2026-07-31 분기(2026-08-12 발표 완료)의 추정
LITE 2026-08-14 0q avg 2.96892 → 실은 2026-06-30 분기(발표 완료)의 추정
     (둘 다 다음 날 08-15 에는 각각 1.32365 / 3.63134 로 굴러감)
```
즉 발표 후 1~2일은 야후 0q 가 아직 굴러가지 않는다. `forward_estimates.py:1048` 에는
이 경우를 잡는 보정("컨센서스가 발표 분기를 가리켜 한 분기 당김")이 있지만,
**원장 경로(app.forward_spread_rows)에는 같은 보정이 없다.** 지금 화면 14행에는
우연히 안 걸렸지만(08-15 스냅샷을 써서), 장치는 무방비다.

### F4 (보통) — forward_spread_rows 가 `today` 를 받으면서 컨센서스는 무조건 원장 맨 끝을 쓴다
`app.py:319` — `cons = entries[-1]...` 에 `as_of ≤ today` 필터가 없다.
지금 실행 결과:
```
스프레드 행수: 14 · today= 2026-08-14
극단 예: SNDK 컨센서스일 2026-08-15 · UCTT 2026-08-15 · KLAC 2026-08-15 ...
```
**14행 중 13행이 today(2026-08-14)보다 뒤인 2026-08-15 스냅샷을 쓰고 있다.**
지금은 "오늘의 가이던스 vs 오늘의 컨센서스" 관측이라 해악이 작지만,
이 함수는 `today` 인자를 공개하고 있어 과거 시점 재현에 쓰는 순간 **곧바로 미래 참조**가 된다.
(치명으로 올리지 않은 이유: 현재 판정·점수에 쓰이지 않고 화면 관측 전용이기 때문.)

또 하나: 가이던스는 최대 140일 묵은 발표에서 가져오는데, 그 뒤에 새 발표가 있어도
가이던스가 있는 옛 발표를 쓴다 → 지금 1건(DIOD 2026-08-05 가이던스, 이후 2026-08-12 발표 존재).

### F6 (경미) — 원장이 아직 단 한 건의 발표도 커버하지 못한다
