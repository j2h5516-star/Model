# 모델 전체 점검 (model-verify)

저장소 주인 지시(2026-08-21): "모든 조건들을 전체적으로 채택 및 포착
가능한지 검증하는 스킬을 만들어 등록·저장하라. 세션이 누락할 때를
대비한다."

## 절차

1. `python3 model_verify.py; echo $?` 를 실행한다 (종료코드 직접 확인 —
   CLAUDE.md 규칙). 시간이 없으면 `--fast` 로 판정 파일만 본다.
2. 출력 해석:
   - **판정 집계**: 채택/미채택/판정 불가 수. 측정결과.md 마지막 회차의
     집계와 눈으로 대조한다.
   - **빠진 등록 가설**: ⛔ 로 나오면 두 경우다 —
     ① 그 가설이 오늘 등록돼 아직 로봇 런이 안 돈 것 (정상 — 다음 런
     확인을 예약할 것) ② 배선 누락 (collect_job 에서 judge 호출이
     빠짐 — 즉시 수리 대상).
   - **옛 코드 경고**: 판정의 code_rev 가 지금 코드와 다르면 다음 런에서
     갱신된다. 이틀 넘게 지속되면 로봇이 안 도는 것 — actions 기록 확인.
   - **포착 창구**: 시장 정배열 폭(H24 띠 안/밖)과 관찰판(이격도30%+
     완성 수). 여기 수가 0 이어도 문제 아님 — 없는 것은 없다고 말한다.
3. 시험도 함께 확인한다:
   `find . -name __pycache__ -exec rm -rf {} +` 후
   `python3 run_tests.py; echo $?` — 종료코드 0 확인.
4. 이상이 있으면 측정결과.md 에 회차 기록을 남기고 수리한다.
   이상이 없으면 짧게 "이상 없음"만 보고한다 (주인은 비개발자 —
   한국어로, 코드 용어 풀어서).

## 주의

- 이 점검은 **읽기 전용**이다 — 어떤 값도 고치지 않는다.
- 새 가설을 등록하면 judge.py 상수에 추가되는 순간 기대 목록에 자동
  반영된다. model_verify.py 를 따로 고칠 필요 없다 (expected_hypotheses
  가 judge 에서 직접 뽑음). 단 judge 에 상수를 안 만들고 등록하면
  점검망에서 빠진다 — 등록 시 상수 필수.
